# Evaluation contract

## Separate the artifacts

A product receipt is an execution record. It can report observed route,
verification, reroute, attempt, timing, token-proxy, and containment facts. It
does not by itself establish a causal performance claim, external correctness,
provider billing, or full-system savings.

A Research certificate is an experiment artifact. It may compare static and
adaptive policies only under a preregistered protocol with matched initial
state, task clusters, external or hidden oracle criteria where available,
complete exploration accounting, and an uncertainty method defined before
analysis.

## Minimum study design

1. Define task clusters, inclusion and exclusion rules, and risk tiers before
   collecting outcomes.
2. Use a fixed baseline and a separately reported best-fixed baseline.
3. Keep model, reasoning effort, speed tier, topology, and verifier as
   independent dimensions.
4. Record every started arm, retry, verifier run, timeout, and source-state
   outcome.
5. Use an external or hidden oracle for correctness when the repository
   verifier is insufficient. Do not relabel a local fixture as an oracle.
6. Report failures, abstentions, quota exclusions, and incomplete cases.
7. Prespecify the uncertainty method and decision rule. Heuristic route bands
   are not calibrated confidence evidence.
8. Report router, system, learning, and speed-ablation effects separately.

## Claim rules

- Never infer causal improvement from a best-of-two winner.
- Do not claim provider economics from normalized token-cost proxy values.
- Do not claim complete end-to-end savings when parent or caller usage is
  unknown or excluded.
- Do not call simulated fixture output live evidence.
- Use the public redacted receipt for disclosure; retain authoritative local
  artifacts only within the approved evidence boundary.
